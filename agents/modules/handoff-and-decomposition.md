**Pin model AND effort on every delegated call — never inherit.** Both runtimes default an unset subagent to the orchestrator's own model/effort, which silently runs delegated work at orchestrator prices — the inverse of the lane table (the scorecard's pre-policy inherited-Fable entries are the local scar tissue). Every delegation names its lane's model and its effort per the mechanical/substantive split; an unpinned delegation is a review finding, same class as a missing preamble. Deliberately running orchestrator-tier subagents (e.g. an exhaustive ultracode session) stays allowed — as an explicit per-call choice, never a silent default. **New-lane onboarding guard (any vendor, Fable↔Astra 2026-09-05):** record REQUESTED settings separately from RUNTIME-OBSERVED model, effort, service tier, and context inheritance, with artifact provenance (session file, footer, harness version) — config and invocation show what was asked for, not proof of what executed; mark unobservable fields UNKNOWN rather than inferring them from the parent or the config.

**Keep in the orchestrator regardless of regime:** task decomposition, architecture/design decisions, reviewing subagent output before presenting, security-sensitive judgment, direct user conversation, and verify≈solve work — novel algorithms, subtle concurrency, security reasoning, tricky migrations: if a diff can't be judged without re-deriving the solution, delegation costs more than inline. Litmus test before delegating: "can I verify this without redoing it?"

**Decomposition: the fake-edge test.** When sequencing delegated steps, ask of each ordering: does step B actually consume step A's output? If nothing real passes between them, the ordering is habit, not dependency — run them concurrently (subject to the sequential-writers rule below for same-worktree writes) and keep true ordering only for real data dependencies. Most linear plans hide two or three fake edges; each one is latency paid for nothing.

**Decomposition: pre-flight shared constraints (multi-wave programs).** Before launching wave 1 of a program, enumerate what every wave will share: (a) resource ceilings the batch will exhaust — dev-server slots, DB locks, CI concurrency; (b) files every wave must touch, which are guaranteed repeat merge conflicts — if a cheap restructure (registry/auto-discovery) removes the hot spot, do that first; (c) the serial costs that scale with wave count — rebase-and-regate cycles onto a moving main, and the orchestrator's own review attention. Those serial costs, not lane capacity, usually set the real concurrency ceiling; a constraint discovered mid-batch is paid by every wave (2026-07-27: a knowable slot ceiling silenced e2e for an entire 13-wave batch, and one 26-file hot spot re-conflicted ~10 times).

**Role dossiers (2026-08-27, Mike-approved, from the Grok Bot evaluation — "a Bot is a job, not a project"):** leaves stay ephemeral (fresh context is a review feature), but role-level learning that isn't defect-shaped no longer gets re-derived per task. Machine-local `~/.claude/roles/<role>.md` files (release-cutter, QA-driver, i18n-runner, judge, …) accumulate role facts the grading loop surfaces; a delegation of that role class prepends its dossier AFTER the preamble. Dossiers hold role knowledge only — standing guards still go in the preamble, defect classes still go to gates (scar-to-gate). A dossier is created lazily, the second time a role recurs. A dossier carries role FACTS, not a reviewer's reject bar: prepending one to a fresh leaf does not reproduce a standing reviewer (the Grok formation's persistent Sieve is the live counter-pattern — EXP-H10 compares the two).

**Every leaf work delegation prompt starts with the contents of `~/.claude/delegation-preamble.md`** (machine-local — carries the standing guards: anti-delegation, stop-before-git, the verification loop, current repo landmines). When the scorecard mandates a new standing guard, update that file — not individual prompts. Prompt-construction rules beyond the preamble:
1. **A repo rule whose violation the local gates reward does not survive by reference** — if the wrong answer passes typecheck/tests locally (e.g. a migration class that only misbehaves in prod infrastructure), restate the rule INLINE in the spec; standing cases go in the preamble, task-specific ones in the prompt.
2. **Debug and redo delegations state the orchestrator's diagnosis explicitly AND as a hypothesis** — instruct the leaf to verify it before acting, with permission to refute; a literal executor handed a diagnosis-as-fact will faithfully implement your error at high fidelity, and a refutation returned is the system working.
3. **Environment-delta injection (2026-07-28):** repos that maintain an environment-delta register (`docs/agents/env-deltas.md` — known local-vs-CI/prod divergences, each entry = surface globs + an inline-able rule) get it consulted at spec-writing time: any entry whose surfaces intersect the task's write-set is restated INLINE in the spec, and the spec's verify anchors use the CI-shaped invocation of the gate, not the local shortcut. Compiled epics do this at compile time (the compile-epic pipeline); ad-hoc delegations do it by hand. The register targets the dominant escaped-defect class — local-green ≠ CI/prod-green (env flags that differ per CI config, migration semantics that differ in prod, deploy-topology skew) — which pre-merge diff review demonstrably cannot catch; only running the divergent environment's shape can.

Drive subagents that write to the same worktree **sequentially** — parallel writers have failed here before (sandboxed git writes). Parallel is fine for read-only exploration.
