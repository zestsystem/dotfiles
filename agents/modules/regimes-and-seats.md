## Regimes — named STRATEGIES (model-agnostic); the director SEAT is config

**ACTIVE REGIME: `director` (since 2026-07-19 — supersedes `fable-director`; for the CURRENT SEAT read `director_seat.current` in `~/.claude/model-economics.json` — never trust a seat name written in this file, which goes stale every flip).** A regime is a strategy; WHO occupies the director seat is landscape config. **The seat ladder lives in `~/.claude/model-economics.json` (`director_seat` block, machine-local, beside the prices)** — flipping seats = a one-line edit there, not a regime change, not a commit. Switching regimes = edit this line + the scorecard's regime note, commit. Dormant strategies are preserved below intact — do not delete or let them rot; they are the fallback positions.

**Regime selector (how Mike decides which line to set):** `director` is the standing default strategy — it answers "how work flows" (orchestrate, delegate, review), which no landscape change has yet invalidated. `default` is a manual, explicitly-scoped per-session opt-in for model testing (see below), never a fallback. Within `director`, the SEAT falls back along the ladder keyed off pool health — the pools have no uniform telemetry, so each seat's flip signal is named in the ladder block (e.g. Fable's meter is read per its lane's credit_status note). The ladder recovers as well as falls: when a flip signal clears (e.g. a confirmed Fable weekly reset with headroom — read BOTH numbers in Settings > Usage), the seat returns to the highest healthy rung. **Mechanically, a session's director is whatever model backs that session** — Mike picks the app; the seat names the DEFAULT pool for orchestration when there's a free choice and the fallback order when a pool walls, not a per-session enforcement. An unproven model backing a session doesn't inherit the seat's trust: its orchestration is a trial and gets graded like one (the k3 precedent — seat provisional until ~3+ graded results).

### Regime `director` (ACTIVE) — one director kernel, seat-specific execution
The strategy is identical under every seat: the seated model owns intent, decomposition, decisions, synthesis, final review, and the outcome. Delegation is an instrument, not the director's purpose. Delegate when at least one concrete benefit justifies the handoff: independent parallel work, context isolation from noisy exploration/tests, a better tool or capability fit, or meaningful meter savings on a bounded task. Keep work inline when it is short, tightly coupled to evolving judgment, ambiguous enough that the prompt would merely move the thinking elsewhere, or cheaper to finish than to specify and review. The director remains accountable for delegated output and must inspect the evidence or diff before accepting it.

**Director handoff contract:** before dispatch, state the outcome, hard constraints, authority boundary, write-set, verification, stop point, and what the leaf must return. Do not prescribe choices that are intentionally left for the leaf to investigate. At fan-in, reconcile every expected result, resolve conflicts against source evidence, record decisions that future work depends on, and run the tiered review appropriate to risk. Same-model delegation is still useful for fresh context, lens diversity, and wall-clock compression; do not claim it creates a capability upgrade.
**Off-meter weighting: the codex (Sol) lane is the default EXECUTOR for delegated work — not just spec-complete implementation — with one UI carve-out; the codex-astra lane (2026-09-05, Fable↔Astra converged, Mike-approved) is the PROVISIONAL Codex-side judgment/review lane beside it (lane table).** All frontend/UI implementation goes to the Claude UI lane — **fable-5-1-low by default; opus-5 is the fallback when the Fable weekly slice walls** (Mike, 2026-09-04: "we use fable on low effort" — supersedes the 2026-09-02 opus-5-default reversal; evidence EXP-H11: quality parity-or-better and 0.57–0.87× wall-clock at 0.93–1.39× plan cost, Mike trading plan headroom for speed — mechanics in the lane table). For substantial or net-new taste-bearing UI, Fable is the design director when available: Fable establishes or adjudicates product feel, hierarchy, interaction, responsive states, and copy; the Claude UI lane implements; Fable reviews the rendered result. Routine UI fixes, established-component assembly, and reference-complete fidelity work may route directly to the Claude UI lane. Fable is “available” when a Fable session/workstream is already active or Mike can start one within current plan/approved-meter headroom; do not spend metered Fable credits beyond standing grants merely to satisfy this preference. If Fable is unavailable, continue on the Claude UI lane against the current reference and design system unless a material design ambiguity remains—surface that ambiguity for Mike instead of silently inventing direction. Never substitute k3 automatically. If both Claude UI lanes are unavailable, surface the lane failure and wait for Mike's direction rather than silently routing implementation elsewhere. Codex bills the ChatGPT Pro meter, so it preserves BOTH the director's own pool and the Anthropic plan; keep the codex weighting hardest everywhere else. This includes hands-on agentic work: computer-use/browser driving and simulator QA runs (Mike: Sol is very good at these — grade under H4). Route to codex (high substantive / low mechanical — settled defaults per the lane table) unless the task is frontend/UI implementation (→ Claude UI lane), needs Fable design ownership under this rule, specifically needs the Claude harness, is exploration (sonnet-explore stays settled), or is a judgment/review role where codex-astra is the provisional first pick (Sol stays selectable).
**Fable under ANY seat: the scoped judgment and design-direction lane.** Epic/initiative kickoffs, planning and decomposition, architecture/design decisions, gnarly debugging or judgment calls, security-sensitive reasoning, taste review of work produced elsewhere, and design direction for substantial taste-bearing UI when available. In that lane, use full reasoning depth and keep judgment-coupled work in the Fable main loop. Fable may finish small or tightly coupled implementation inline; delegate bounded execution when the director-kernel test above says the handoff pays. “Fable writes the spec and never implements” is not a goal in itself. When Fable owns a UI workstream, it reviews rendered states rather than treating a code diff as proof of taste or fidelity.

It is not a prerequisite for Sol to direct or review. Reachability and authorization are defined by the runtime adapter — in Codex, a Fable architecture rung requires a Mike-started interactive Fable workstream; the diff-scoped taste consult does not qualify; otherwise use the fresh-context capable-model fallback. This pre-implementation rung does not replace the post-implementation adversarial pair, machine gates, or the director's mandatory final read on money/auth/migration surfaces. A skipped rung may become 🏛 ARCHITECTURE-REVIEW-DEBT on the governing PR/issue — naming the unresolved decision and the activation gate — only while the work remains reversible or behind a gate; closure requires an actual judgment disposition, never the passage of time; an irreversible release/activation checks for unresolved architecture debt and remains blocked until the rung occurs or Mike explicitly accepts the risk. **"Independent" is a procedure, not a statistic (Fable↔Astra, 2026-09-05):** separate context, freedom to reject the brief's assumptions, and the consult's own evidence gathering against source — never a claim that two frontier models make statistically independent errors (that correlation is UNKNOWN; shared-corpus speculation neither proves equivalence nor defeats the value of cross-model review).

### Regime `default` (DORMANT — manual opt-in, scoped to model-testing sessions) — no delegation policy, vanilla harness behavior
Exists so a new/unfamiliar model can be evaluated on its own merits, unrouted — no delegation policy fighting with what's actually being tested. When active: the delegation lane table, the pin-model-and-effort requirement, and the scorecard/delegation-log bookkeeping are all suspended for the session. The harness runs as it would with no protocol in effect — whatever model started the session just does the work directly, and any subagents it spawns aren't required to be pinned to a lane. Use it for things like "try gpt-5.6-sol solo with no Codex-lane assumptions" or "see how k3 performs unrouted" — the session itself becomes the test article, not a proxy for how the lane table would use that model.
- **Scope discipline:** opt in explicitly per session (Mike says so, or a session is expressly framed as a model trial) and opt back out just as explicitly when the trial ends — never let a session drift into `default` just because routing felt inconvenient, and never let it persist past the trial. The regime LINE at the top of this file stays on `director`; `default` is a per-session override noted in that session, not a line edit.
- **Still in effect even under `default`:** worktree isolation, the git safety protocol, honest verification, and the Ultra/fast-mode bans. This regime suspends the DELEGATION policy only, not basic safety practice.
- **Findings feed back, not bypass:** a promising or disappointing result from a `default`-regime trial is exactly the kind of ~1-datapoint signal the scorecard's "~3+ graded results" bar exists for — log it as a normal graded task (executor = the model under test) once the session's done, same as any other lane trial. `default` changes how the session runs, not whether the result counts.
