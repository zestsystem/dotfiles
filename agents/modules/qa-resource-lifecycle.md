**QA/dev resource lifecycle (2026-07-31 — twice-escaped: orphaned QA resources from interrupted sessions exhausted swap AND disk, crashing the host app and killing in-flight leaves):** heavy local resources (emulators/simulators, dev-server stacks, tool servers, watch-mode processes) and their disk artifacts (QA-created emulator/simulator devices, build caches) are a leak class the leaf ledger cannot see — it tracks leaf processes, not what they spawned. Rules: (1) every leaf that boots a heavy resource carries the teardown duty (standing preamble guard, same date); (2) a booted resource no live claim or session names is reclaimable on sight — directors sweep orphans at session start alongside `leaf-sweep`, scoped kills by PID only, human-terminal-parented stacks excluded (`orphan-sweep` is the mechanical gate per scar-to-gate; until it lands, sweep by hand: emulator consoles + ppid-1 watch/dev processes cwd'd in worktrees); (3) QA-created device artifacts follow create-implies-delete — shared pool devices are the named exception and get age-swept instead; (4) host memory/disk headroom is a pre-flight shared constraint: check it before local fan-outs, and a wave that would breach it routes remote per the substrates section; (5) the session-start sweep includes a container-engine health probe — time a bare `docker info` and treat >~10s as hung; do NOT wrap it in `timeout`, which is a GNU coreutils binary macOS does not ship (2026-08-17: `timeout 15 docker info || echo DOWN` printed DOWN on a healthy 0.8s engine, because the shell failed on `command not found` — a false hang verdict that would have "restarted" a working engine and stalled the sweep). A hung engine (OrbStack vmgr, Docker Desktop) wedges every DB-locked run at FULL lock-timeout cost while looking like lock contention (2026-08-07 scar: a 4h engine hang starved runs for 3600s each and presented as a wedged peer suite); a dead socket gets the engine restarted per the reclaim recipe BEFORE any test queues.
