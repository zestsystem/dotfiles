## Rate delegated work — ratings evolve the routing

After every delegated task (any runtime, any vendor): one-line capability note in the summary (executor, usable as-is?, rework needed) AND a scorecard entry (date, task category, grade, one-line why) AND one JSON line appended to the delegation log via `log-delegation` (schema + canonical executor enums in the scorecard header; `ext_tokens` = real Codex usage-footer count, never a placeholder). Fable taste consults get logged too (executor `fable`, the task's own category) — they are spend the digest must see.

**Review-role evidence rubric (Fable↔Astra, 2026-09-05 — "green gates, zero fixes" cannot grade a reviewer):** a review or skeptic datapoint records confirmed findings, known misses against an ADJUDICATED reference set, false positives, severity calibration, and verification coverage. The reference set is revisable: novel verified findings count even when absent from the key, and disputed reference findings get adjudicated before any arm is graded. Distinguish introduced from pre-existing defects, FILED findings from merely NOTICED concerns, and PLAUSIBLE candidates from VERIFIED findings; report checks that were unavailable (no dependencies installed, no DB) explicitly. Severity calibration is a review-effectiveness property, not only taste. Several arms on one task are ONE task cluster — one routing datapoint, however many models ran.

**Grade directors separately from their leaves.** A director datapoint scores the orchestration outcome: intent and acceptance criteria, decomposition quality, routing and handoff loss, steering, fan-in reconciliation, defects caught in final review, unnecessary handoffs, operator attention, and whether the final result shipped. Do not infer director quality from leaf grades. During the Sol trial, log one `codex-gpt-5.6-sol-director-high` datapoint per representative completed workflow after leaf grades are recorded; include the leaf roster and any director rework in the note. Three results are the minimum for a provisional verdict, not an automatic promotion. Director executor enums (2026-08-31; `fable-5-1-director` added 2026-09-02 at the 5→5.1 flip — never blend with `fable-5-director`; Astra strata added 2026-09-05): `fable-5-director` | `fable-5-1-director` | `opus-5-director` | `k3-director` | `codex-gpt-5.6-sol-director-high` | `codex-gpt-6-astra-director-solo` | `codex-gpt-6-astra-director-multi` — one datapoint per completed directed workflow, logged forward-looking; past programs get grades only where the full workflow evidence is reconstructable (no retroactive folklore). Seat confidence counts DIRECTOR datapoints only — executor/judgment grades do not accredit a seat. EXP-H9's matched Fable baseline gets a real `fable-5-director` grade when evidence-complete.

**Open experiments are routing-active, not backlog.** The scorecard carries an "Open experiments" block beside its routing adjustments, mirrored machine-readably in `~/.claude/experiments.json` (machine-local). A task matching an open experiment's trigger routes per the experiment's arms without asking Mike — subject to the standing limits (never on irreversible blast radius without explicit go-ahead; shadow arms bill subscription/plan lanes only, never metered credits). Enforcement is mechanical at the logging chokepoint, not honor-system: `log-delegation` fires a reminder on every logged task matching an open experiment and counts quota via `"exp":"<id>"`-tagged log lines, and the weekly digest audits progress — a STALE or QUOTA-REACHED flag is an action item for the first director who sees it (run it deliberately, or conclude: verdict into the routing adjustments, entry deleted from experiments.json). Every experiment declares trigger, arms, quota, decision rule, and staleness date at creation — anything without all five is a hypothesis, not an experiment, and stays in the hypotheses section.

Before delegating, consult the scorecard for the task category and apply its routing adjustments. Adjust routing on patterns (~3+ consistent results), not single data points. Measurement is two-axis: the correctness grade AND a `taste` score 1–5 (anchors in the scorecard header); a lane averaging taste ≤3 over ~3+ tasks is a demotion signal even at A-band correctness. When a lane's underlying model changes generation, version the executor name (e.g. `codex-gpt-5.6-sol-xhigh`, `sonnet-6`) so grades never blend across models — and at the same flip, re-probe that lane's generation-bound behavior guards (the ones carrying a model generation in their heading, e.g. the 5.6 behavior guards): cheaply test whether each observed behavior still reproduces on the new generation, retire what doesn't with a scorecard note, and never inherit a guard on faith. Economics ground truth: `npx ccusage daily`, the weekly digest (launchd agent runs `~/.config/claude-code/bin/delegation-report.sh` Mondays 9:23am → `~/.claude/delegation-reports/`, tracking orchestrator-cost-per-merged-PR and all-in-cost-per-merged-PR), and `~/.claude/model-economics.json` for meter semantics — subscription lanes judged by headroom/value-captured, metered lanes by real dollars.

**Significant protocol changes are debated before they are written (Mike, 2026-09-05 — standing rule; Astra's amendment folded in).** A significant change to routing, authority, seats, or review gates gets a fresh-context CHALLENGE before adoption — cross-vendor, in the challenging model's native harness when reachable and authorized (the Fable↔Sol 2026-08-31, Fable↔Atlas 2026-08-31 and Fable↔Astra 2026-09-05 rounds are the shape); the CLI path to the same model is an acceptable substitute when the app is unreachable. Record the proposal, the evidence, the disagreements, the disposition, and the approval; write "Fable↔X converged" only for actual agreement (record disagreements as disagreements) and "Mike-approved" only after his actual approval. Unavailable cross-vendor access never blocks drafting or routine factual corrections (enum additions, price bumps, dated scars need no debate); material unresolved adoption decisions go to Mike. The debate is logged like any delegation (executor = the model debated, `cat` = writing).

**Rule-challenge ritual (2026-07-30) — scar rules are re-tested, never just accumulated.** Scar tissue ratchets: rules only get added, and an obsolete guard silently taxes every session while training directors to trust rules that no longer bind. Quarterly — and immediately on any seat flip or lane generation change — the sitting director challenges the oldest CAPABILITY-COMPENSATION rules: guards written for a specific model's observed behavior. Only that class rots with model progress; world-facts (billing, quotas, auth mechanics), meter economics, and coordination contracts (claims, write-sets, review tiers) are not model-dependent and are exempt. Challenge = a cheap re-probe of whether the behavior still reproduces; a guard that fails to reproduce is retired from this file with a scorecard note (git history keeps the original). Challenge rules individually, never bulk-delete — dated scars are individually testable, and deletion destroys the record of why. For whole-model re-baselining ("what does the model do with no rules at all"), the instrument is the `default` regime, not deletion.
