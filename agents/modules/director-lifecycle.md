- **Directors are metered processes — shift lifecycle is meter hygiene (2026-08-27, Mike-directed, from the reset-day burn analysis):** a director whose program is landed ENDS its shift — STATUS, hand residual watches to a peer or a scheduled wakeup, terminate — instead of idle-holding; every idle heartbeat at full context is real spend (~400–530K cache-read), so a director that must hold arms 20–30-min cadences minimum and queues long waits instead of babysitting them. **Context resets are COMPACTION, not fresh sessions (2026-09-29 pilot, Mike-approved: "go ahead with the pilot, 600K"; "the fable based rule should disappear"). This retires the Fable-era gate of 2026-08-27 (WARN 250K / RECYCLE 400K cache-read per message → HANDOFF → fresh session → end old), which was a meter rule with no quality basis.** Within an assignment a director resets context by in-process AUTO-COMPACTION, enforced by the harness rather than remembered: `CLAUDE_CODE_AUTO_COMPACT_WINDOW=600000` in the `env` block of `settings.json` (effective trigger ≈ window − reserved output (≤20K) − 13K ≈ 567K; read from the process environment at session start, so a changed setting reaches NEW sessions or a live `/autocompact` change; `DISABLE_AUTO_COMPACT` defeats it). Compaction keeps the process: background waiters, session crons, artifact watches and Mike's conversation thread survive (observed 2026-09-29: a compaction mid-grant, and every waiter and the heartbeat cron delivered afterwards); a fresh session drops all of them (scar 2026-09-28: a self-/clear stalled an overnight grant until Mike asked). Evidence (8 longest director transcripts, ~20K tool calls, 30 auto-compactions; fresh-context skeptic review by a different model, verdict adopt-with-amendments): self-inflicted slips cluster right after ANY reset (matched windows around the same boundaries: 8/1,200 before vs 35/1,200 after, decaying over ~100 calls), while steady-state slip rates did not rise with context length — an association (mostly Fable-seat data, task-phase confounded), not proof, so this is a PILOT. Cost still scales with context (every message re-reads it); a 600K window vs the ~968K default saves roughly a third of cache-read in a uniform-growth model (modelled, not measured) for about one extra compaction per day at overnight growth rates. Rules: (1) Fresh sessions ONLY at a completed epic/authority boundary (a grant for one epic must not leak into the next), unrecoverable process state, a seat change, or when independent fresh review is needed — and a live-grant session ends only after its successor has acknowledged and owns the wakes; never self-/clear. (2) Keep a versioned on-disk checkpoint (the HANDOFF file, six fields) current at milestones so a compaction lands on curated state; no mandatory WIP commits (compaction keeps files). (3) After any compaction, reconcile checkpoint + summary + live state (git/gh/ps/cron list) before consequential writes, and revalidate mutable ids (PR/run/SHA/worktree) from source before consequential actions throughout the session, not only right after the reset. (4) `director-context` (or `--self <session-id>`) at session start and every heartbeat is TELEMETRY: occupancy per session (deduplicated, chronological, all models), compactions recorded, the configured window; exit 3 = OVER = occupancy past the window, i.e. the window is not in force for that session — keep working, it is not a recycle order. (5) Pilot review after 5 compactions or 2026-10-06, whichever first: matched incident/obligation audit (regex hits AND non-hits, missed obligations, wrong-target actions, repair time) plus deduplicated usage; microcompaction is a separate experiment. Under meter pressure cap concurrent fable directors at 2–3 and weight the codex lane hardest: day-1-of-window intensity front-loads the whole week's pool (2026-08-27: 4–5 concurrent long-shift directors did ~45% of the prior week's ENTIRE fable output on reset day alone). Executor-shaped work ground inline in a judgment-lane session is the same class of routing miss as an unpinned delegation. **Grant precedence:** under an active continuous-work grant this rule NEVER ends the shift while claimable work exists anywhere on the board — the grant-mode/overnight rules govern, and idling on a quiet zone stays the protocol miss it always was; the shift-end applies only when the program is genuinely landed (empty global frontier, only external waits left). Even then the grant survives the session: park the waits in queues and arm a scheduled re-entry (cron/schedule routine) that re-checks the frontier in a FRESH session — cheaper than a full-context session held as an alarm clock, and it survives app restarts, which held sessions don't (2026-08-13). "Keep working until Mike stops it" is unchanged; what changed is that waiting happens at long cadences in cheap contexts.
