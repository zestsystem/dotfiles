## Tiered review at every handoff

Every subagent's output gets reviewed BEFORE it is used, built on, or presented — automatic, per handoff, never batched to the end (errors compound). Scale depth to blast radius, cheapest rung first:

1. **Machine checks (zero orchestrator effort):** typecheck/lint/tests on code diffs; open/render generated files; and, on any PR whose risk warrants it (the request-by-risk rule in orchestrator hygiene), the review-bot pass (whichever bots the repo actually runs — CodeRabbit on the UTC repo ONLY, per the repo-scope note in orchestrator hygiene; Bugbot/claude-review/Devin where installed), whose findings are swept and dispositioned per the never-ignored rule in orchestrator hygiene before merge. For haiku-tier mechanical work, this plus a diff skim is the whole review.
2. **Orchestrator diff-read:** standard work — read the diff/deliverable, not the transcript, depth scaled to risk.
3. **Delegated deep review:** large or complex diffs go to a cheap reviewer agent; the orchestrator reads the findings and spot-checks. **Fresh context is mandatory:** the reviewer gets the diff/deliverable plus the spec, NEVER the worker's transcript or session context — a reviewer sharing the worker's context is the worker grading its own homework at a higher price. A freshly spawned leaf given a SELF-CONTAINED brief satisfies this; a native child that forks the parent's history does NOT — Codex full-history forks inherit the worker's context and cannot be overridden (use `fork_turns: "none"`; Codex adapter), and a Claude Agent-tool child sees only its prompt. The rule also exists so no one "helpfully" pastes the transcript in (Astra-found contradiction, corrected 2026-09-05).
   - **Exception — money paths, auth/RBAC, migrations:** always the orchestrator's own final read, plus a pre-merge run of the TARGETED integration tests for that surface even where the repo's broader policy defers integration suites to a deploy gate (minutes of tests against hours of escaped-regression cleanup); no cheap-reviews-cheap rubber-stamping there.
   - **Dual controls on any diff that adds or tightens an authorization check:** verify BOTH — the refused actor is refused (negative), AND a named legitimate actor at the edge of the new rule still passes (positive). A negative control proves the guard fires; it does not prove the guard isn't too broad, and the escaped case is precisely the legitimate actor nobody thought to enumerate.
4. **Panel verify (top rung — triggered, never the default):** N fresh-context skeptics per finding, each prompted to REFUTE through a distinct lens (correctness / currency / is-the-source-real, or domain equivalents); EVIDENCE adjudicates, votes only prioritise investigation (rule below). Triggers: the finding would drive an irreversible or expensive action (prod migration, money-path change, external publication, lane promotion/demotion); a surprising claim is load-bearing for the deliverable; or the merged report of a fan-out IS the deliverable (audits, research sweeps). Everywhere else rungs 1–3 stay the default — the panel is deliberate spend, logged like any delegation. Identical skeptics buy redundancy; distinct lenses buy coverage — prefer lenses.

Subagent self-reviews, green-test claims, and cited precedents are claims to verify, not conclusions — check them against the repo, not against their own justification. Never let review depth hit zero: one bad merge outweighs months of saved tokens.

**Evidence beats votes (Fable↔Astra, 2026-09-05 — replaces majority-vote adjudication everywhere a panel or pair disagrees):** one validated counterexample defeats the claim it contradicts regardless of how many reviewers were reassured. Validation is an executable reproduction or a checkable source-level argument (a runnable repro is not always possible); votes only decide what gets investigated first. Record the evidence, the disposition, and the unresolved uncertainty. **Capability vs availability:** outcome records separate artifact quality from execution conditions — model/service errors, quota interruptions, tool/access denials, harness or config failures, and judgment misses are distinct causes (several may apply; attribution may be UNKNOWN); an availability failure changes a lane's operational suitability without automatically counting as a capability failure.

**Blocking findings from ANY independent rung get a written disposition (2026-08-31):** a blocking finding from a review bot, Sol audit, adversarial pair, or architecture/design consult cannot be closed by the director's final read alone — fix it, refute it with evidence on the record, or escalate to Mike. This generalizes the review-bot never-ignored rule to every independent rung; the final read sits on top of the rungs and never silently drops a blocker.

**Scar-to-gate rule (2026-07-28):** a deterministic review check enforced by director attention is a defect queue, not a gate — the recurring escape classes (untranslated locales, DML-in-migration, env-dependent test expectations, UI-changed-without-e2e) all escaped repeatedly WHILE their prose rules stood, including one guardrail missed 5× in a single nightly. When the same defect class escapes twice, or a mandated review check is fully mechanical (a script could decide it), the fix is a repo-level gate — a CI check, lint rule, or pre-merge script — not another preamble/spec sentence: write the check, wire it into the PR gate, and retire the manual duty (leave a pointer in the preamble/scorecard so reviewers know it's covered). Prose rules are for judgment; scripts are for determinism. Directors' review attention then concentrates on what only judgment can catch.

**Surgical e2e expectation rule (2026-09-03, Mike-directed, from the release-gate flake study — 6 of 19 red releases were stale expectations, and the last four web PRs merged with the e2e-impact gate red):** a PR that changes a test id, copy, or component anatomy updates every spec that references it IN THE SAME PR, and that spec diff is reviewed as its own artifact, separate from the app diff. Surgical means the spec hunks touch selectors, copy, and anatomy only: no removed `expect`/`assertVisible`, no added `skip`/`fixme`, no widened timeout or loosened matcher without a one-line justification on that hunk (`spec-lint: <spec> — <why>` in the PR body is the machine-readable form). Evidence is owed for the DIRECT impact set — specs matched by test id or route — which is small and runs in minutes before merge; the transitive import closure is informational and rides the nightly. Enforcement is mechanical (scar-to-gate): the spec-diff lint gate flags the forbidden hunk shapes, and the e2e-impact gate demands `rc=0` evidence only for direct impact. A stale expectation that reaches a release cut is a protocol miss on the PR that changed the UI, not on the cutter.

**Green-to-skill rule (2026-08-27, Mike-approved, from the Grok Bot evaluation — the capability twin of scar-to-gate):** scar-to-gate freezes failures into CI; this freezes successes into automation. The 2nd–3rd time a director hand-drives the same multi-step operational flow (a release ceremony, a QA sweep, a vendor-console dance), compile it into a skill/justfile recipe carrying a six-field contract: when to use it, required inputs/access, the exact sequence, how to validate the result, what to return, and what requires approval. The approval field is mandatory — it is the difference between an employee and an incident. Until frozen, a repeated manual flow is a capability queue, same smell as a defect queue.

**Recurring-job policy + the quota-furnace rule (2026-08-27, Mike-approved, same source):** every scheduled/cron/sentinel/routine job declares up front: owner, cadence + timezone, input source, output destination, approval boundary, missing-data behavior (report the failure — never quietly reuse stale data), and idempotent retries so a re-run cannot double-send. Cadence economics: polling a connected service all day burns an order of magnitude more quota than batching to a session-end report for identical output — poll-style jobs default to batch-and-report, and any recurring job under a 1-hour cadence carries a written justification on its declaration. Applies across lanes and meters.
