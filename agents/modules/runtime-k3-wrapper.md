- **k3 lane mechanics — `kimi-claude` (machine-local wrapper in `~/.local/bin`; key resolved `$KIMI_K3_API_KEY` → Doppler `mikeyim/nixos` secret `KIMI_K3_API_KEY` → macOS Keychain as offline fallback):** it launches Claude Code against Kimi's Anthropic-compatible endpoint with EVERY model tier (fable/opus/sonnet/haiku AND `CLAUDE_CODE_SUBAGENT_MODEL`) mapped to `k3`.
  - **The `k3[1m]` alias was RETIRED (broke the lane 2026-07-29) — plain `k3` IS the 1M model** (`/v1/models` reports `context_length` 1048576), so the suffix bought nothing and now hard-fails every call; the wrapper sets the 1M context via `CLAUDE_CODE_MAX_CONTEXT_TOKENS`/`AUTO_COMPACT_WINDOW`, not via the model id.
  - **Doppler-read gotcha for any future wrapped lane:** the service token that can see the `mikeyim` project is scoped to `~/.config`, so a read from an arbitrary worktree cwd fails with "Could not find requested project 'mikeyim'" — pin every `doppler secrets get` to that directory (subshell `cd`), never the caller's cwd.
  - **Use `ANTHROPIC_AUTH_TOKEN`, never `ANTHROPIC_API_KEY`, in any wrapped lane (2026-07-29 scar):** `ANTHROPIC_API_KEY` is gated by Claude Code's per-key approval list in `~/.claude.json` (`customApiKeyResponses`), and answering that "use this API key?" prompt with **No** permanently pins the key's last-20 chars into `rejected` — after which INTERACTIVE sessions silently ignore the key and fall through to the OAuth **login selector**, while headless `-p` keeps working because it never consults the approval list. That asymmetry is a nasty diagnostic trap: it presents as "the k3 lane is fine for leaves but can't hold the director seat", looks like a dead key, and tempts a login that would silently bill the Anthropic plan for a Kimi-metered session. `ANTHROPIC_AUTH_TOKEN` bypasses the gate (Kimi accepts Bearer auth); a stale `rejected` entry then becomes harmless but stays a landmine for anyone reverting to `ANTHROPIC_API_KEY`. Verify a wrapped lane's INTERACTIVE path explicitly — a green headless `-p` probe does NOT prove the director seat works.
  - **k3 leaf from any session** = `kimi-claude -p --dangerously-skip-permissions "<preamble + prompt>"` — headless one-shot, the k3 analogue of `codex exec`; preamble first, explicit stop point, log executor `k3`. The permission flag is REQUIRED for write tasks (2026-07-21 scar: without it, headless `claude -p` cannot approve Edit/Write, so the leaf explores, stages a plan, and bails asking for interactive approval — a whole quota-burning run producing zero diff); it is the same trust level as the codex lane's `--yolo`, bounded by the preamble's guards, so keep prompts narrowly scoped.
  - **Wrapped-lane auth guard (2026-07-20 scar):** a wrapper lane launched from INSIDE an agent session inherits the parent's `CLAUDECODE`/`CLAUDE_*`/`ANTHROPIC_*` env, which can make the child prefer the parent's OAuth over the wrapper's API key — surfacing as a bogus "invalid/expired API key" 401 (plus minutes-long auth stalls) while the same key works interactively and via direct curl. The wrapper must scrub ALL inherited `CLAUDECODE|CLAUDE_*|ANTHROPIC_*` vars before its own exports (kimi-claude does since 2026-07-20; apply the same scrub to any future wrapped lane).
  - **Diagnosis order on a wrapped-lane 401: READ THE ERROR BODY FIRST** — Kimi returns `"type":"authentication_error"` for non-auth faults, notably a retired/unknown model id ("Your model id does not exist, recognized as other:k3[1m]. Please set model id as `k3`" — the 2026-07-29 scar, where a perfectly valid key looked dead for a day); then inherited auth env, then key validity via direct curl, THEN quota/reset — never declare a key dead, split keys per context, or demote the lane on the 401 alone. The one-line ground-truth probe (bypasses the whole harness): `curl -sS https://api.kimi.com/coding/v1/messages -H "x-api-key: $KEY" -H "anthropic-version: 2023-06-01" -H 'content-type: application/json' -d '{"model":"k3","max_tokens":16,"messages":[{"role":"user","content":"reply OK"}]}'`; `GET /coding/v1/models` lists the currently-valid ids.
  - **Inside a k3-backed session** (interactive `kimi-claude`), Agent-tool/Workflow `model` pinning is a NO-OP — `model: sonnet` silently runs k3 on the Kimi meter, so the sonnet/haiku/opus lanes are unavailable in-session; other lanes are reached via bash (`codex exec`, or a plain `claude -p` for Anthropic-billed work). The Claude UI lane rule (fable-5-1-low default, opus-5 fallback) still applies: launch the UI worker through bash; never treat an in-session Agent call as an acceptable frontend substitute.
